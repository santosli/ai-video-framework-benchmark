# 测试方法与边界

## 比较的对象

比较“同一个 AI，按各自官方 Skill，用某个框架完成给定视频任务”的实际工作流，不是手工精调后的框架理论上限，也不是最短代码量竞赛。模型固定为 Codex `gpt-6.1-sol` / `high`。Remotion 4.0.535，HyperFrames 0.8.152，官方技能固定到提交号。底层渲染浏览器来自各自官方配置，不宣称两个框架的浏览器实现或 CPU 调度完全一致。

原机为 Apple Silicon Mac、32 GB 内存，软件编码；两家存在同机并行，时间数据保留但不据此做严格的导出速度排名。复测应记录自己的 CPU、GPU、内存、系统、Node、FFmpeg、浏览器及模型设置；别把性能差异都归因于框架。

## 相对公平性的前提

1. 每个独立测试使用全新对话上下文、独立工作目录；不把另一框架或其他场景的生成代码、结果、技术反馈带入。
2. 同场景、同版本给双方相同文件字节、素材、原声、任务与验收条件，开跑前记录 SHA-256。公开导出时再次逐组核对了 54 份输入版本的双方一致性。
3. 依赖、官方 Skill 和共用输入在制作前准备并冻结。参赛者不能换素材、下载模板、更新依赖；读取技能与最终冻结文件校验有记录。
4. 修改阶段另起上下文，给各自对应的初版副本和共用 v2 更新包，保留 v1 供核对；不是两家都从同一家的成品出发。
5. 同预算、同种技术反馈模板，不因作者偏好只给一方美术指导。失败、超时和无可用基线要如实保留。

独立目录、只读权限与哈希检查是防止无意污染的实验措施，同一个操作系统用户仍有更广的读取能力；这不是敌对代码的安全隔离证明。模型可能受其服务端实现、工具环境、随机性和未公开的全局配置影响，所以称“相对公平”，不声称完全消除所有变量。

## 两批的实际范围

| 项目 | 第一批 | 第二批 |
| --- | --- | --- |
| 场景 | T01–T06、S01–S06、P01–P06，共 18 个 | K01–K09、M01–M09，共 18 个 |
| 阶段 | 初版 + 一次指定修改 | 只有初版 |
| 每家有效运行数 | 36 | 18 |
| 个人盲评对象 | 修订版 | 初版 |
| 字幕输入 | 共用文本和给定时间轴 | 只给文本；从音轨自行对齐 |
| 技术复核 | 逐任务内容、修改和保留项检查 | 自动音频门槛 + 固定种子抽查 9 条，另加门槛失败及“两家都不好”项 |

第一批最初计划多次重复，后来缩为每项取第 1 次有效重复；已运行的 r2 不计入本轮比较。中性环境冒烟、输入预检、作废运行与故障修复期间的重跑不混入 108 次有效样本。不能用这份提示词包的数量反推整轮实际总算力支出。

第二批运行中发现验收器的单声道折算使正确双声道人声被误读成约 +3 dB，另有连续说话时音乐检测依赖停顿的问题。修复后，收到错误反馈污染的 6 条和中断的 2 条作废重跑；未受错误反馈影响的输出经修正门槛复查后保留。K07 原音乐开头很轻且有转场音效，音乐数值门槛不适用，改作记录和人工抽查。读者复测时不能把验收器错误当成框架错误，也不要按审美挑选重跑结果。

## 预算和记录

- 初版写码、自查和技术纠错累计 1200 秒，最多 2 次技术反馈。
- 修改累计 600 秒，最多 1 次技术反馈。
- 完整导出等待与写码计时分开，累计导出预算 900 秒；原服务暂停完整导出等待的作者计时，预览等待计入自查。
- 记录第一张可检查预览的等待、作者等待、最终完整导出和总导出时间。不得把最短导出、第一次失败和最终导出随意混成一个“速度”指标。
- 框架顺序按固定种子抽签（第一批 20261014，第二批 20261016）。种子属于原轮方法记录；本仓库没有重新分发私有执行队列和自动调度器，读者应在自己的完整队列上冻结抽签结果，不宣称相同种子就自动重建同一运行队列。

## 先偏好，再查合格

只有作者一人盲评，先隐藏框架名称后选更偏好 A／B／两家都好／两家都不好；它不是多评委客观评分。

技术检查另看：

- 数据、计数、标签、公式、页面状态及资源身份是否准确。
- 字幕时序、人物／说话人对应、给定时间窗是否落实；第二批自主对齐不能和第一批给定时间轴混称同一种任务。
- 原声是否按要求保持、有没有偏移或变速，是否重复叠加音轨，混音／峰值／音乐是否符合该场景。
- 横竖屏重排、边角裁切、人物保护区及手机宽度下的小字可读性。
- 修改指定项是否完成，没让改的内容、时序、布局或其他版本是否保住。

P06 批量五版须交全部 5 份，V03 固定主票，不从五版中挑最好的一条。S05 是空间坐标和动画展示，不是真实物理引擎模拟。第二批的版式和字幕并非全部自动门槛，“自动检查通过”不能写成“全部人工复核通过”。

## 消耗、结论与可复现程度

Token 汇总含大量缓存输入；输入 Token 多约 36% 不等于真实账单贵约 36%。没有逐项隔离 Skill 体积影响，也没有完整人工介入工时，不能据此证明某框架天生更贵或总工时更高。

公开包保留了数据、约束、场景和原始任务文本；源码输入中可再分发的部分随包提供，原人像、声音、音乐、字体、设备模型等不提供二进制。替换这些素材，尤其人物保护区、音频时间轴、长页坐标，必须同步修改自己的共用规范、记录差异，并对双方使用同一更新包。这样的结果是方法复测，不能冒称原输出的逐帧复制。

108 份提示词中 107 份直接取自留存工程，1 份因工程内原文被交接文本覆盖，按执行器固定模板和场景修订指令重建；108 份均与运行前记录的 SHA-256 一致。对应核对清单见 `prompt-provenance.json`。这证明提示词一致性，不证明 AI 会产生相同视频。
