# 输入与素材

## 已提供的内容

共 54 份场景版本，包含原任务 `brief.md`、事件、时长／尺寸、验收条件、字幕文本／第一批时间轴、自制数据，以及现成网页、React 组件、SVG 等文本资产。`input-manifest.json` 为公开版重建清单，移除了原机器绝对路径、原始素材制作过程和私有运行记录；保留原清单哈希、逐文件哈希和大小。

每份公开清单标注 `export_kind: public-source-only`。`included: false` 的 285 次文件引用涉及重复使用的字体／许可 PDF、视频、声音、PNG 和 GLB；这是引用次数，不是 285 个不同素材。它们没有悄悄改成占位文件，也不会被检查工具假报为已齐备。

## 如何补齐

| 输入类型 | 你需要准备什么 | 换素材时一并检查 |
| --- | --- | --- |
| 字体 | 自行合法获取原 MiSans，或双方统一使用同一种有权使用的字体 | 文件名／路径、字宽、行高、换行及小字可读性；替换需披露 |
| 人物口播／双人对话 | 自有或可授权的出镜片段、对应原声音轨 | fps、时长、声道、人物保护区、说话人和首尾完整句；不要把原人物坐标直接套到新脸 |
| 科普配音 | 按本版本文字录制或合成同一份音轨，再同时给两家 | 原长、停顿、事件及第一批字幕时间轴；第二批不向参赛者提供对齐答案 |
| BGM、试听段、提示音 | 同一份有权使用的音频 | 原文件电平、从零开始的基准、窗口和淡入淡出；响度不同的替代曲不能直接比较原音乐检测数字 |
| PNG／截图／插图 | 若同目录有 SVG，可用同一工具、同一字体栅格化；其余自行制作同内容素材 | 像素尺寸、文字、产品状态、图文身份和裁切边界；不是每张 PNG 都有 SVG 源 |
| 长网页 | 按 P04 的事件和区块坐标准备 5000 px／6500 px 长图 | 新按钮位置、滚动终点、停留区；换版须同步更新坐标 |
| 3D 设备 | 合法模型、屏幕录屏和材料配置 | 几何、UV、屏幕帧号、颜色及相机；不能只改扩展名伪装原模型 |

固定音轨通常是 48 kHz。大部分输出横屏，S04/P06 原生竖屏，T04 修改版也变竖屏；以各版本 `expected.json` 为准。人物底片可能是 720p，不能把输入分辨率和目标输出分辨率混为一谈。

## 替换后怎么报告

1. 为自己建立一份共用输入包，写新文件哈希和每项差异；保留仓库原清单作参照。
2. 先中性预检，再给双方完全相同的目录副本。使用固定模型、技能、依赖和预算，检查目录没有互相引用。
3. 记录“复用原提示词 + 替换哪些资产／时间轴／模型”。如果第一批重录声音导致时长变化，不能沿用原字幕时序后把必然错位算成框架错误。
4. 想测字幕自主对齐，就选第二批；自己为验收准备的金标准时间不要泄露给制作 AI。

`check-input --exact` 通过只表示文件字节与原始清单吻合，不能替代版权、语义或视频质量审核；普通 `check-input` 的外部素材存在性通过也不等于完成技术验收。
